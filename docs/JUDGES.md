## 5 recommendations
1. **Frame it as "The System That Gets Better," with Trust but Verify as how it works.** Show a held-out set of about 15 broken-object prompts. Each run is scored with binary checks: prints, fits in MuJoCo, survives a load test. Show the pass rate climbing across runs, and **one live rollback** where a harness change regresses the score and gets reverted. This wins Ivan, Mike and the MongoDB judges. Software Archaeology is the weakest fit; use it at most as one line ("rebuild a discontinued part from a photo").
2. **Make the physics engine the independent verifier.** A separate model (e.g. Gemini, if the designer is Muse Spark) reads the MuJoCo results and can veto the design. Line: *"The designer never grades its own homework. Physics does."*
3. **Open with one real broken thing and a printed part in hand.** The freezer-door latch: show the photo, say one sentence, then hold up the part. It's a home and family moment (Mike), a small-blocker fix (Ivan), and real engineering (Sana). Keep the robot dog to a 10-second "what's next" for Rajashekar. Live RL training is too slow and too risky to demo.
4. **Use Meta Muse Spark as the designer agent, and say "point your glasses at it."** That targets the $5k Meta prize and Mike's wearables platform. Only show glasses capture if it actually works. Otherwise just say it as the vision.
5. **Collect the sponsor tracks cheaply.** Register the agents on Agentverse with the Chat Protocol (required for the Fetch $5k). Keep fix memory and the eval history in MongoDB. Close on the number: *"Run 1: 4/15 parts fit. Run 6: 12/15. One regression caught and rolled back."* (These numbers are placeholders. Use the real ones from our runs.)
